- **Clean Architecture / Onion / Hexagonal** — dependency inversion everywhere
- **DDD** — aggregates, entities, value objects, domain events, repositories, factories
- **Event Sourcing** — event store, projections, snapshots, replay
- **CQRS** — separate read/write models
- **Actor Model** — supervision trees, mailboxes, location transparency
- **Microservices patterns** — circuit breakers, bulkheads, sidecars
- **Module/Plugin** — hot-swappable, versioned, capability-negotiated
- **All protocols abstracted** — GraphQL, REST, gRPC, WebSocket interfaces behind traits
- **Schema registry** — Protobuf/Avro/JSON Schema evolution
- **API Gateway** — rate limiting, auth, transformation
- **Service Mesh** — mTLS, traffic splitting, retries, observability
- **CRDTs** — merge semantics with proofs
- **Multi-region active-active** — conflict-free replication
- **Polyglot persistence** — SQL, time-series, graph, object store abstractions
- **Data Mesh** — domain-oriented ownership
- **Event-driven** — event bus, sagas, choreography
- **Temporal workflows** — durable execution, compensation
- **Actor supervision** — fault isolation, restart strategies
- **Lock-free data structures** — where provably correct
